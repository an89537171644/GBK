# Установка автономной исследовательской версии в Windows

Это пакет для сетевого рецензирования, а не офлайн- или самодостаточный
дистрибутив. При первой установке обязательно подключение к интернету: архив
содержит фиксированный список зависимостей, но не сами пакеты Python.

## Требования

- Windows 10 или Windows 11, 64-разрядная редакция;
- Python 3.11 x64 с установленным Python Launcher (`py`);
- доступ на запись в папку программы;
- подключение к сети при первой установке фиксированных зависимостей.

ЛИРА-САПР, SCAD, сервер баз данных, веб-сервер и права администратора для работы
автономного расчётчика не требуются.

## Установка из подготовленного wheel

1. Распакуйте полученный ZIP в отдельную локальную папку.
2. Убедитесь, что в каталоге `wheel` находится один переданный файл `.whl`.
3. Запустите `INSTALL_FROM_WHEEL.cmd`.
4. Скрипт до установки автоматически сверит SHA-256 wheel с ожидаемым хешем,
   зафиксированным сборщиком и манифестом.
5. Скрипт создаст изолированное окружение `.venv`, установит фиксированные
   зависимости из `requirements/runtime-py311.lock`, затем проектный wheel с
   `--no-deps`, не изменяя системную среду Python.
6. После установки запустите `RUN_JSON_USER.cmd` для контрольного примера либо
   `RUN_INTERACTIVE.cmd` для ручного ввода. Эти пользовательские скрипты сохраняют
   окно после завершения.

`VERIFY_PACKAGE.cmd` до установки проверяет SHA-256 манифеста, размеры и SHA-256
всех записанных файлов. Это контроль целостности от случайного изменения или
повреждения, но не криптографическое подтверждение подлинности. Доверие к
источнику архива и репозиторию GitHub проверяется отдельно.

Версии в `runtime-py311.lock` сняты 2026-07-18 с нейтрального тестового профиля
проекта. Их допуск для данного архива подтверждается только успешной блокирующей
проверкой `standalone-windows` в чистом Windows/Python 3.11 окружении.

## Установка из исходного репозитория

Разработчик может передать скрипту полный путь к исходной папке проекта:

```bat
INSTALL_FROM_SOURCE.cmd "C:\path\to\GBK"
```

В указанной папке должен находиться `pyproject.toml`. Такой режим предназначен
для разработки и проверки, а не для передачи конечному пользователю.

## Командный режим

Автономный модуль поддерживает:

```bat
python -m sp63_core.standalone
python -m sp63_core.standalone --input-json INPUT.json --output-dir OUTPUT --json
```

Скрипт `RUN_JSON.cmd` использует включённый пример, однако допускает передачу
собственных путей первым и вторым параметрами. Он не ставит паузу и предназначен
для автоматизации и CI. Для ручного запуска используйте `RUN_JSON_USER.cmd`,
который передаёт те же параметры и сохраняет окно. Все пути вычисляются
относительно расположения скрипта посредством `%~dp0`, поэтому папка может
содержать пробелы и кириллические символы.

## Поля входного JSON

| Поле | Единица | Точное программное значение | Допустимое значение |
|---|---:|---|---|
| `case_id` | — | Технический идентификатор расчёта; не включать ФИО, email, подписи или локальные пути | Непустая после обрезки строка, не более 100 символов, без управляющих символов |
| `b_mm` | мм | Ширина прямоугольного сечения | Конечное число `> 0` |
| `h_mm` | мм | Высота прямоугольного сечения | Конечное число `> 0` |
| `cover_mm` | мм | Расстояние от грани бетона до наружной поверхности хомута; нормативная интерпретация не утверждена | Конечное число `> 0` и `< h_mm` |
| `stirrup_diameter_mm` | мм | Диаметр хомута, используемый в геометрии | Одно из: `6`, `8`, `10`, `12` |
| `concrete_class` | — | Класс бетона текущего ULS-каталога | `B15`, `B20`, `B25`, `B30`, `B35`, `B40` |
| `longitudinal_rebar_class` | — | Класс продольной арматуры текущего ULS-каталога | `A400`, `A500` |
| `stirrup_rebar_class` | — | Класс поперечной арматуры текущего каталога | `A240`, `A400`, `A500` |
| `moment_kNm` | кН·м | Неотрицательный модуль изгибающего момента; знак не выбирает грань | Конечное число `>= 0` |
| `shear_kN` | кН | Неотрицательный модуль поперечной силы | Конечное число `>= 0` |
| `tension_face` | — | Явно выбранная растянутая грань в локальной системе | `local_y_min` или `local_y_max` |
| `element_type` (необязательное) | — | Фиксирует область элемента | Только `rectangular_beam`; при отсутствии используется оно же |
| `load_duration` (необязательное) | — | Фиксирует маршрут длительности | Только `short`; при отсутствии используется оно же |

Классы и диаметры в таблице — текущий программный каталог, а не новое нормативное
утверждение; свойства материалов требуют инженерной проверки.

Числа в `input/beam_example.json` — только демонстрационные исходные данные, не
коэффициенты, нормативные значения или рекомендации по проектированию. До
инженерного утверждения сопоставления локальных осей с реальным элементом
пользователь обязан отдельно проверить выбранную грань.

## Каталоги результата

Для каждого отдельного расчёта задавайте отдельный каталог результата. Каталог,
принятый standalone-модулем, управляется программой: не помещайте в него
произвольные пользовательские файлы. При повторном запуске программа может
удалить из него известные служебные артефакты предыдущего запуска, чтобы не
показать устаревший отчёт.

После расчёта главным пользовательским входом служит верхнеуровневый
`standalone_index.html`. Не начинайте просмотр с raw `workflow/index.html`.
`OPEN_RESULTS.cmd` лишь открывает папку и не выбирает правильный отчёт.

## Передача инженеру

Передавайте только верхнеуровневый `standalone_review_bundle.zip`, который
санитизирован и проверен программой. Не передавайте весь каталог `output` или
внутренний `workflow/deterministic_report.zip`: они предназначены только для
локальной работы и могут содержать абсолютные пути компьютера автора.

Для пакетной приёмки поле `standalone_review_metadata.json`
`.code_identity.code_identity_status` должно быть
`recorded_from_launcher_requires_manifest_match`, а SHA-256 из
`.code_identity.build_id=wheel-sha256:<sha256>` должно совпадать с
`wheel_sha256` в доверенном `standalone_manifest.json`. Маркер сам по себе не
подтверждает подлинность. Для `source-unverified` статус равен
`unavailable_open_question`; такой результат не проходит передачу как испытание
собранного пакета.

## Ограничения безопасности

- не копируйте `.venv` и сформированные отчёты в Git-репозиторий;
- сверяйте SHA-256 файлов по `standalone_manifest.json` и
  `standalone_manifest.sha256`;
- не используйте результат в проектировании;
- при `fail` или `outside_applicability` не интерпретируйте диагностические данные
  как несущую способность;
- статус `pass` отдельной технической проверки не означает общий результат,
  инженерный допуск или разрешение проектного применения;
- перед инженерным применением требуется отдельная проверка и разрешение.
