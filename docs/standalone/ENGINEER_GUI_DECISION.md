# Решение по инженерному интерфейсу автономной версии

```text
requires_engineer_review = true
project_use = false
```

## Решение

Для исследовательской автономной версии прямоугольной балки под Windows выбран
тонкий настольный интерфейс на `Tkinter`.

Статус решения: `CONFIRMED` как решение по удобству программной оболочки.
Инженерный допуск расчётных результатов этим решением не подтверждается.

Решение применяется только к следующему маршруту:

- Windows 10/11;
- подготовленный автономный пакет на Python 3.11;
- один обычный железобетонный элемент прямоугольного сечения, работающий как
  балка;
- только `load_duration=short`;
- ручной ввод уже предусмотренных автономным контрактом исходных данных;
- запуск существующего детерминированного standalone-контроллера;
- просмотр верхнеуровневого отчёта и папки результата.

## Архитектурная граница

Tkinter является только локальной оболочкой. Интерфейс:

- собирает значения полей существующего `StandaloneBeamInput`;
- передаёт их существующему standalone-контроллеру;
- отображает возвращённый статус и ссылки на сформированные файлы;
- извлекает для экранной сводки только разрешённые поля из повторно проверенного
  верхнеуровневого `standalone_review_bundle.zip`, связывая их с точными
  исходными данными текущего запуска;
- показывает условную схему сечения только по проверенным исходным размерам,
  без вычисления новых инженерных величин и без изображения фактической
  раскладки стержней;
- повторно fail-closed проверяет текущие исходные данные, безопасные локальные
  ссылки, семантику публичного ZIP и совпадение build identity перед открытием
  или экспортом;
- не содержит и не дублирует расчётные формулы;
- не изменяет каталог материалов, числовые коэффициенты, нормативные ссылки,
  правила применимости или алгоритмы подбора;
- не заменяет CLI/JSON-маршрут, который сохраняется для диагностики и
  автоматизации.

## Экранная сводка и условная схема

Экранная сводка может показывать исходные данные в пользовательских единицах,
публичные статусы, диагностические строки предложенного продольного и
поперечного армирования, а также перечень отключённых проверок. Она не показывает
`Mult`, коэффициент использования по изгибу, внутренние промежуточные значения,
свойства материалов или нормативные коэффициенты.

Графическая часть схемы содержит только прямоугольник `b × h`, условный контур
хомута, введённое значение `cover`, выбранное обозначение `local_y_min` или
`local_y_max` и модули `|M|`, `|Q|` как текст. Рядом допускаются только текстовые
строки уже проверенных диагностических предложений арматуры; положения и слои
стержней не рисуются. Схема не является рабочим чертежом, схемой армирования,
проверкой размещения или утверждением физической ориентации элемента.

Любое изменение поля немедленно очищает сводку и схему. Ошибка проверки ZIP,
контрольных сумм, build identity, защитных флагов или связи с текущими исходными
данными блокирует показ значений и все действия с результатом.

Если детерминированный маршрут не выбрал проходящий диагностический вариант,
HTML и ZIP по-прежнему не выдаются. Интерфейс показывает доступную причину
отбора и предлагает проверить исходные данные и диапазон вариантов, но не
утверждает неработоспособность сечения и не назначает исправленный размер или
армирование. Производные сообщения об отсутствии HTML/ZIP не должны скрывать
первичную причину, а независимые нарушения защитных флагов остаются видимыми.

Доступность `Tkinter` должна проверяться при сборке/испытании Windows-пакета. При
его отсутствии запуск должен завершаться безопасным читаемым сообщением, а не
переходить на другой GUI-фреймворк и не продолжать расчёт скрытно.

## Обязательные защитные ограничения

- В окне постоянно видны `project_use = false` и
  `requires_engineer_review = true` либо их однозначные русские эквиваленты.
- Статус `pass` отдельной проверки не показывается как общий инженерный допуск,
  утверждение проекта или разрешение применения.
- `fail`, `outside_applicability` и `review_required` не скрываются и не
  преобразуются в положительный результат.
- ML не включается в автономный интерфейс и не представляется как расчётчик.
- Интерфейс не формирует расчётную модель здания, нагрузки или сочетания и не
  требует ЛИРА-САПР либо SCAD.
- Каждый сформированный результат остаётся предметом инженерной проверки.

## Что данное решение не утверждает

Решение не утверждает нормативные формулы, значения материалов, коэффициенты,
знаковую конвенцию, сопоставление локальных граней реальному элементу,
достаточность области применимости или пригодность программы для проектного и
производственного использования.

## Критерий пересмотра

Расширение интерфейса на иные элементы, сечения, платформы, расчётные режимы,
веб-доступ или другой GUI-фреймворк требует отдельного решения и инженерной
проверки. Настоящее решение не является общим отказом от остальных положений
K64.
